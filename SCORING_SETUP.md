# Playoff Picks — Scoring System (as built)

The Google Sheet behind this app has a full scoring engine built in. This
documents how it actually works, so future changes don't have to be
reverse-engineered from formulas.

**Multiplier rule:** every round a player's team survives, that team's
*next* round of points doubles again — 1x (Wild Card) → 2x (Divisional) →
4x (Conference Championship) → 8x (Super Bowl). A team that loses stops
generating points entirely (it's out of the playoffs).

**Cumulative scoring:** the multiplier applies per round, and a player's
season-long total is the sum of every round they've played so far, each at
that round's own multiplier — not just whatever the current round happens
to be.

## Tabs

- **Picks** — one row per entrant, written by the Apps Script behind
  `index.html`. Columns: `name, QB, qbteam, RB1, rb1team, RB2, rb2team, WR1,
  wr1team, WR2, wr2team, WR3, wr3team, TE, teteam, submittedat, Round`.
- **RosterState** — one row per entrant per slot (7 rows × 8 entrants = 56
  rows). Columns: `Name, Position, Player, Team, StartRound,
  StartRoundIndex, Alive, Streak, Multiplier, RoundPoints, ScoreThisRound,
  CumulativeScore`.
  - `Name`/`Position`/`Player` (A–C) are generated by array formulas that
    melt `Picks` into long form — `A2` stacks `Picks!A2:A9` seven times,
    `C2` stacks each position's player column (`Picks!B2:B9`,
    `Picks!D2:D9`, …). If you ever need to rebuild these, note that
    `INDEX()` with an array row-argument does **not** broadcast under
    `ARRAYFORMULA` in this sheet — use array-literal range stacking
    (`{range1;range2;...}`) or `XLOOKUP` instead, both of which do
    broadcast correctly.
  - `Alive` = TRUE unless the player's team was eliminated in an earlier
    round than `CurrentRound` (looked up from `TeamStatus`).
  - `Streak` = `CurrentRound!CurrentRoundIndex - StartRoundIndex` while
    alive, else 0 (i.e. rounds survived so far).
  - `Multiplier` = `2^Streak` — this round's multiplier only.
  - `RoundPoints` = the player's raw PPR points for whatever round is
    currently active (looked up from `PlayerPointsByRound` via
    `CurrentRound`).
  - `ScoreThisRound` = `RoundPoints * Multiplier` — this round's
    contribution only.
  - `CumulativeScore` = sums every round from Wild Card through
    `CurrentRound` (inclusive), each round's raw points × that round's own
    multiplier (1/2/4/8), but only counting rounds the team was still alive
    for. This is the number that actually feeds the leaderboard.
- **NeedsRepick** — `=FILTER(RosterState!A:D, RosterState!G:G=FALSE)`.
  Auto-lists anyone whose player just got eliminated, so you know who needs
  a replacement pick.
- **RoundConfig** — static reference table: `Round, RoundIndex,
  BaseMultiplier` (WC=0/1, DIV=1/2, CONF=2/4, SB=3/8). Mirrors the `2^Streak`
  math for reference; not itself read by the live formulas.
- **CurrentRound** — the one cell you update each week: `CurrentRound`
  (dropdown: WC/DIV/CONF/SB) and `CurrentRoundIndex` (0–3). This is what
  advances the whole sheet to the next round.
- **TeamStatus** — manual entry after each round: `Team, EliminatedRound,
  EliminatedRoundIndex`. Leave a team's row blank while it's still alive;
  fill in the round it lost once it's out.
- **PlayerTeamMap** — `Player, Team`, generated by
  `=UNIQUE(FILTER({...}, {...}<>""))` melting all 7 position/team column
  pairs out of `Picks`. **Don't type directly into a cell here** — it's all
  one array-formula spill anchored at `A2`; editing any cell inside it
  (e.g. to fix a team typo) deletes the whole array and leaves a single
  literal value behind. Fix data errors at the source in `Picks` instead —
  this tab picks up the correction automatically.
- **NeededPlayers** — QA tab confirming every drafted player has a row in
  `PlayerRoundStats` (`Status` = "In PlayerStats" or blank if missing).
- **PlayerRoundStats** — manual entry per player per round: `Round, Player,
  PassYds, PassTD, Int, RushYds, RushTD, Rec, RecYds, RecTD, Fumbles,
  PPRPoints (formula), Key (formula)`.
  - `PPRPoints` = `PassYds/25 + PassTD*4 - Int*2 + RushYds/10 + RushTD*6 +
    Rec*1 + RecYds/10 + RecTD*6 - Fumbles*2`, rounded to 2 decimals.
  - `Key` = `Round & "|" & Player` — a lookup key used elsewhere.
- **PlayerPointsByRound** — one row per player, pivoted from
  `PlayerRoundStats`: `Player, WC_PPR, DIV_PPR, CONF_PPR, SB_PPR`.
- **Leaderboard** — final standings: `Rank, Medal, Name, Total PPR`, with
  medal emoji for the top 3. `Total PPR` = `SUMIF(RosterState!A:A, <name>,
  RosterState!L:L)` — i.e. sums that entrant's 7 `CumulativeScore` values.
- **PublicLeaderboard** — `=ARRAYFORMULA(Leaderboard!A2:D9)` live-linked to
  `Leaderboard` (previously this was a stale manual copy — fixed so it now
  auto-updates). Published to the web as CSV for `leaderboard.html` to
  fetch.
- **PublicRoster** — `Name, Position, Player, Team, Points`, built from
  `=ARRAYFORMULA({RosterState!A2:D57, RosterState!L2:L57})`. One row per
  entrant per player, with that player's `CumulativeScore`. This is what
  `leaderboard.html`'s click-to-expand-a-name feature reads — it needs to
  be published to the web as CSV the same way `PublicLeaderboard` is (File
  → Share → Publish to web → select the `PublicRoster` sheet → format
  "Comma-separated values"), and that CSV URL pasted into
  `leaderboard.html`'s `ROSTER_CSV_URL` constant.

## Weekly workflow

1. After a round's games finish, go to `TeamStatus` and fill in
   `EliminatedRound`/`EliminatedRoundIndex` for any team that lost.
2. Add that round's raw stats for every player who played, as new rows in
   `PlayerRoundStats`.
3. Once you're ready to move to the next round, update `CurrentRound` /
   `CurrentRoundIndex` on the `CurrentRound` tab.
4. `RosterState`, `Leaderboard`, `PublicLeaderboard`, and `PublicRoster`
   update themselves — no other steps needed.

## Known quirks (cosmetic, not functional)

- `RoundConfig!BaseMultiplier` duplicates the `2^Streak` math for reference
  but isn't read by any live formula — informational only.
